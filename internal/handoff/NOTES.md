# Handoff 契约与原始历史降级边界

## 文档契约

使用 YAML front matter 与规范约定的 8 个固定 Markdown 二级标题。仅接受 `schema_version: 1`、合法来源 ID、RFC3339 生成时间、完整 Git 元数据；来源未知时显式写 `unknown`，Git 未知字段可为空。拒绝缺节、重复节、未闭合代码围栏、仅有省略号的模板和明显凭据泄漏。`Marshal` 固定章节顺序，`ContinuePrompt` 额外原样强调硬约束。

验证器只证明结构完整与已知敏感形式未泄漏，无法证明模型总结涵盖了所有事实或用户约束。Skill 与生成提示要求逐字引用用户硬约束、区分已验证结果和推测；恢复后仍需核对实际代码状态。工具输出和助手文本不能升级为用户指令。

## 原始历史提取

优先使用原生恢复及官方结构化会话读取。原始 JSONL 仅是最后降级路径：支持 Claude 的 `user`/`assistant` 消息、文本与工具块，以及 Codex 的 `response_item`、`event_msg`、function call 等常见事件主干。未知事件跳过，损坏或截断的 JSON 行不补造内容；不提取 thinking、reasoning、图片与 base64。新版本的私有日志格式可能需要补充识别规则。

提取结果为 JSONL，每行包含外层 `role`（`user`、`assistant`、`tool`）和 `text`。文本正确转义，日志内伪造来源标签不会变成新的事件。总结模型只能从外层 `role=user` 的解码文本提取用户约束。已识别的用户文本不静默截断；超出显式大小上限时返回错误。重复事件不擅自去重，以免误删用户重复强调的指令。

明显凭据在发送总结模型之前脱敏，图片数据省略；调用边界还须逐值脱敏已知解密密钥。通用模式无法识别任意未知私有字符串。文档中的凭据被拒绝而非悄悄改写，以避免无提示地修改用户约束。

`SummaryPrompt` 标记 `raw-file-fallback` 并要求声明可能信息丢失；`StructuredSummaryPrompt` 用于官方 `thread/read` 的历史，标记 `dead-session-resume`，不会伪称原始文件降级。`LivePrompt` 只是提交给当前活 agent 的生成请求；外部 Relay 不声称能够读取该 agent 的内存上下文。

## 路径与测试

会话查找限定在显式原生目录的 `projects` 或 `sessions` 下，最多遍历 50000 项、8 层目录，不跟随符号链接；同 ID 多个结果时报错，不猜测哪份更新。文件读取由共享 `safeio` 校验路径、普通文件类型和大小。

测试覆盖文档往返、原文硬约束强调、代码围栏、非法/缺失元数据、空模板、普通约束不误改、凭据脱敏幂等、长消息、损坏行、图片/thinking 忽略、来源伪造、路径穿越和非 Git 工作目录。全部使用虚构凭据与隔离临时目录。
